## Задание 1. Исследование моделей и инфраструктуры

### 1. Сравнение LLM-моделей

| Критерий               | Локальные (HuggingFace / Ollama)                                                                | Облачные (OpenAI GPT-4o)                   | Облачные (YandexGPT)                   |
|------------------------|-------------------------------------------------------------------------------------------------|--------------------------------------------|----------------------------------------|
| **Качество ответов**   | Хорошее (Mistral 7B, LLaMA 3.1 8B), уступает GPT-4o на сложных рассуждениях                     | Отличное                                   | Хорошее, особенно для русского языка   |
| **Скорость**           | На CPU - медленно (5–20 tok/s). На Apple Silicon через Ollama - приемлемо (~15–30 tok/s для 7B) | Быстро (~50–80 tok/s, зависит от нагрузки) | Сопоставимо с OpenAI                   |
| **Стоимость**          | Только инфраструктура (0 руб. за токен)                                                         | $0.005–$0.015 за 1K токенов                | От ₽0.2 за 1K токенов                  |
| **Развёртывание**      | Ollama: `docker run ollama/ollama` + pull модели. Просто, работает на ARM                       | API-ключ + вызов HTTP                      | API-ключ + регистрация в Яндекс.Облаке |
| **Конфиденциальность** | Полная: данные не покидают машину                                                               | Данные уходят в США                        | Данные уходят в Яндекс                 |

**Вывод:** для данного учебного проекта выбрана **OpenAI GPT-4o-mini** через API - быстрая генерация, высокое качество ответов, простая интеграция через `langchain-openai`. В продакшне для QuantumForge рекомендовался бы локальный вариант (Ollama) из соображений конфиденциальности.

### 2. Сравнение моделей эмбеддингов

| Критерий                 | `all-MiniLM-L6-v2` (локальная) | `paraphrase-multilingual-MiniLM-L12-v2` (локальная) | `bge-base-en-v1.5` (локальная) | `text-embedding-ada-002` (OpenAI) |
|--------------------------|--------------------------------|-----------------------------------------------------|--------------------------------|-----------------------------------|
| **Языки**                | Только английский              | 50+ языков (EN, RU и др.)                           | Только английский              | 100+ языков                       |
| **Размер эмбеддинга**    | 384                            | 384                                                 | 768                            | 1536                              |
| **Скорость индексации**  | Быстрая (~500 docs/s на CPU)   | Быстрая (~400 docs/s на CPU)                        | Умеренная (~250 docs/s)        | Зависит от сети и rate-limit      |
| **Качество поиска**      | Хорошее (EN)                   | Хорошее для кросс-языкового поиска (RU→EN)          | Лучше на технических текстах   | Отличное                          |
| **Стоимость**            | 0 руб.                         | 0 руб.                                              | 0 руб.                         | $0.0001 за 1K токенов             |
| **Работа без интернета** | Да                             | Да                                                  | Да                             | Нет                               |

**Вывод:** используем **`paraphrase-multilingual-MiniLM-L12-v2`** - поддерживает 50+ языков включая русский, размер эмбеддинга такой же как у `all-MiniLM-L6-v2` (384), работает на CPU без API-ключей. Это критично для проекта: документы базы знаний на английском, а пользователи задают вопросы на русском - кросс-языковый поиск работает корректно только с мультиязычной моделью.

### 3. Сравнение векторных баз FAISS и ChromaDB

| Критерий                     | FAISS                                               | ChromaDB                                                     |
|------------------------------|-----------------------------------------------------|--------------------------------------------------------------|
| **Скорость поиска**          | Очень высокая (оптимизирован под similarity search) | Высокая, чуть медленнее FAISS                                |
| **Скорость индексации**      | Высокая                                             | Умеренная                                                    |
| **Персистентность**          | Ручная (`index.save()`/`index.load()`)              | Автоматическая (SQLite по умолчанию)                         |
| **Фильтрация по метаданным** | Не поддерживается нативно                           | Поддерживается                                               |
| **Сложность внедрения**      | Минимальная: `pip install faiss-cpu`, нет сервера   | Чуть сложнее: требует отдельного процесса или Docker-сервиса |
| **Поддержка**                | Требует больше кода для CRUD (нет удаления по id)   | Полноценный CRUD                                             |
| **Стоимость инфраструктуры** | Нет (in-process библиотека)                         | Нет для self-hosted                                          |

**Вывод:** для учебного проекта с фиксированной базой знаний выбираем **FAISS** - меньше движущихся частей, не нужен отдельный сервис, хорошо работает в Docker-контейнере. Индекс сохраняем вручную в `faiss.index`.

### 4. Варианты конфигурации сервера

Рассмотрено 4 варианта для развёртывания RAG-бота:

#### Вариант A - Минимальный (CPU-only)
- **LLM:** Ollama + Mistral 7B (GGUF Q4, ~4 GB RAM)
- **Эмбеддинги:** `all-MiniLM-L6-v2` (sentence-transformers)
- **Векторная БД:** FAISS
- **Железо:** 8 GB RAM, любой современный CPU
- **Плюсы:** работает прямо сейчас, 0 стоимость, всё в Docker
- **Минусы:** генерация ответа ~10–20 сек на вопрос

#### Вариант B - Продвинутый локальный (GPU NVIDIA)
- **LLM:** Ollama + LLaMA 3.1 8B
- **Эмбеддинги:** `bge-base-en-v1.5`
- **Векторная БД:** FAISS
- **Железо:** 16 GB RAM, NVIDIA RTX 3060 8 GB VRAM
- **Плюсы:** быстрая генерация (~100 tok/s), хорошее качество
- **Минусы:** нужна GPU-машина

#### Вариант C - Гибридный (локальные эмбеддинги + облачный LLM)
- **LLM:** OpenAI GPT-3.5-turbo / GPT-4o (API)
- **Эмбеддинги:** `all-MiniLM-L6-v2` (локально)
- **Векторная БД:** ChromaDB
- **Железо:** 8 GB RAM, любой CPU
- **Плюсы:** высокое качество ответов, эмбеддинги бесплатны, быстрая генерация
- **Минусы:** контекст документов уходит в OpenAI, ~$5–20/мес при активном использовании, нужен API-ключ

#### Вариант D - Полностью облачный
- **LLM:** OpenAI GPT-4o
- **Эмбеддинги:** `text-embedding-ada-002`
- **Векторная БД:** ChromaDB (или Pinecone)
- **Железо:** минимальное (только для оркестрации)
- **Плюсы:** лучшее качество, масштабируется
- **Минусы:** все корпоративные данные в облаке, высокая стоимость при масштабе

### Итоговая рекомендация

**Выбран Вариант A** как основа для данного проекта:

| Компонент        | Выбор                                                         |
|------------------|---------------------------------------------------------------|
| **LLM**          | OpenAI GPT-4o-mini (API)                                      |
| **Эмбеддинги**   | `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2` |
| **Векторная БД** | FAISS                                                         |
| **Запуск**       | Локально (`docker compose`)                                   |

**Обоснование:**
1. OpenAI GPT-4o-mini - высокое качество при низкой стоимости (~$0.15/1M токенов), простая интеграция.
2. Мультиязычные эмбеддинги - пользователи могут задавать вопросы на русском, документы в базе на английском.
3. FAISS проще ChromaDB для однократной индексации фиксированного корпуса документов.
4. Локальный запуск без Docker - меньше инфраструктурного оверхеда для разработки.

## Задание 2. Подготовка базы знаний

### Выбранная предметная область

**Вселенная:** Game of Thrones (gameofthrones.fandom.com)
**Причина выбора:** богатый, хорошо структурированный фандом; 30+ страниц по персонажам, локациям, организациям и концепциям; LLM хорошо знает оригинал - это позволяет честно проверить работу RAG после подмены терминов.

Оригинальная вселенная переименована во **вселенную Valdros** (аналог Westeros/Essos).

---

### Скачивание и очистка текстов (`docker compose up scrape`)

Скрипт обращается к MediaWiki API (`action=parse&prop=wikitext`) и очищает wikitext:

- удаляет `<ref>`, HTML-комментарии, внешние ссылки
- убирает шаблоны `{{...}}` (6 итераций для вложенных)
- разворачивает викиссылки `[[Link|text]]` > `text`
- удаляет табличную разметку и HTML-теги

Итог: **41 файл** в `knowledge_base_raw`, охватывающих:
- 21 персонажа
- 8 локаций
- 5 домов и фракций
- 7 концепций и объектов

---

### Замена ключевых терминов (`docker compose up replace_terms`)

**Словарь `terms_map.json`** содержит 209 замен, организованных по категориям:

| Категория                | Примеры замен                                                              |
|--------------------------|----------------------------------------------------------------------------|
| Персонажи (полные имена) | Jon Snow > Kael Dorn, Daenerys Targaryen > Lyra Ashveil                    |
| Псевдонимы               | The Hound > The Stonehound, Littlefinger > Silvertongue                    |
| Дома                     | House Stark > House Dorn, House Lannister > House Greyfel                  |
| Фамилии (одиночные)      | Stark > Dorn, Lannister > Greyfel, Targaryen > Ashveil                     |
| Локации                  | Winterfell > Frosthaven, The Wall > The Veil, Braavos > Silverhaven        |
| Объекты                  | Iron Throne > Stone Throne, Valyrian steel > Embersteel                    |
| Фракции                  | Night's Watch > Veil Guard, Dothraki > Kolvari, Wildlings > Freeborn Clans |
| Религия и магия          | Lord of Light > Lord of Radiance, White Walker > Frost Wraith              |

**Логика замены:** термины сортируются по убыванию длины, чтобы «House Stark» заменялось раньше «Stark» - иначе возникли бы частичные совпадения.

**Результат:** 41 файл в `knowledge_base/` - те же документы, но без единого упоминания оригинальных терминов GoT.

---

### Проверка уникальности базы

Пример фрагмента из `knowledge_base/Jon_Snow.txt`:

> *Kael Dorn, born Aegon Ashveil, is the son of Kira Dorn and Rhaegar Ashveil, the late Prince of Ashveil Isle. From infancy, Kael is presented as the bastard son of Lord Eddran Dorn...*

Ни один из оригинальных терминов (Jon Snow, Targaryen, Stark, Winterfell, Dragonstone) в базе не фигурирует. LLM не сможет ответить "по памяти" на вопросы об этой вселенной.
